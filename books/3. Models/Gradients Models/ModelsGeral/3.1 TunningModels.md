# MODEL TUNING & OPTIMIZATION

## Introduction
Model Tuning is the architectural refinement of a Machine Learning system. It is the process of moving beyond default settings to find the "Sweet Spot" between a model that is too simple (**Underfitting**) and one that is too complex (**Overfitting**). 

Instead of just "running a model," Tuning is an engineering workflow used to maximize specific performance metrics—such as **Recall** for safety-critical tasks—by optimizing how the model sees the data and how its internal mathematical engine operates.

---
# 1. PILLAR: DATA STRATEGY (Data)

This pillar focuses on optimizing the model's "fuel." The way data is selected and prepared defines the performance limit the algorithm can achieve. A great model with poor data strategy will always underperform.

# 1.1 FEATURE SELECTION (Types & Methods)

The goal is to provide the model with only the cleanest signals, removing noise that can cause false patterns or overfitting.

---

### **WHY?**
1.  **Reduced Overfitting:** Less redundant data means less chance of the model making decisions based on "noise" or statistical coincidences.
2.  **Improved Accuracy:** By removing irrelevant columns (e.g., "eye color" to predict diabetes), the model focuses on the true drivers of the target.
3.  **Speed & Efficiency:** Models with 5 columns train and run much faster than models with 500. This saves memory, processing power, and money.
4.  **Multicollinearity Removal:** Avoids having two columns saying the same thing, which can confuse linear models.



---

### **TYPES & CATEGORIES**

#### **1. Filter Methods**
Independent of any machine learning algorithm. They rely on the statistical characteristics of the data (**Math only**).
* **Correlation (`.corr()`):** Measures the linear relationship between feature and target.
* **Variance Threshold (`VarianceThreshold()`):** Removes columns where the values don't change much (low variance = low information).
* **SelectKBest:** Selects the $K$ best columns based on statistical tests.
    * *Regression:* `f_regression`, `mutual_info_regression`.
    * *Classification:* `chi2`, `f_classif`.
* **Best for:** Quick "brute-force" removal of irrelevant features before training.

#### **2. Embedded Methods**
The selection happens **during** the model training. The model itself decides what is important through its internal logic.
* **SelectFromModel (`SFM`):** Uses attributes like `.feature_importances_` (Trees) or `.coef_` (Lasso) to drop features below a certain `threshold`.
* **Best for:** Fast, smart selection that understands the specific logic of the algorithm (Linear vs. Non-linear).

#### **3. Wrapper Methods**
Use a specific model as a "black box" to evaluate subsets of features iteratively by training and testing multiple times.
* **RFE (Recursive Feature Elimination):** Starts with all features and removes the weakest one by one.
* **SFS (Sequential Feature Selection):**
    * *Forward:* Starts with 0 and adds the best one.
    * *Backward:* Starts with all and removes the worst.
* **Best for:** Maximum precision when you have high processing power and a smaller number of features.



---

### **SKLEARN TOOLKIT**
`sklearn.feature_selection`

> **The `.fit()` vs `.fit_transform()` Logic:**
> * **Filter Methods:** Since they don't involve training a complex model, we often use `.fit_transform()` to get the data ready in one go.
> * **Wrapper/Embedded:** We use `.fit()` to let the model "learn" the importance, and then we use `.get_support()` to see the winners.

#### **The `get_support()` Bridge:**
Sklearn transforms data into **Numpy Arrays**, which means column names are lost. To recover them, use:

```python
# Returns a boolean mask of the selected columns
mask = selector.get_support()

# Map the mask back to the original DataFrame header
selected_columns = X.columns[mask]

# Rebuild your DataFrame with names
X_new = pd.DataFrame(selector.transform(X), columns=selected_columns)
```

### 1.2 DIMENSIONALITY REDUCTION
The goal is to condense information from many features into fewer new variables, preserving the data's essence while reducing computational cost, improving correlation, and enabling better visualization.

* **WHY USE IT?**
1. **Information Compression:** Transforms complex data (like MNIST's 784 pixels) into a few components without losing the primary patterns.
2. **Visualization:** Reduces data to 2D or 3D, making it possible to see clusters and groupings.
3. **Noise Removal:** Helps the model focus on the directions where the data actually varies, discarding irrelevant details.

**METHODS**
1. **PCA (Principal Component Analysis):** An **unsupervised** method. It ignores the target ($y$) and focuses solely on finding the axes of maximum variance in the data ($X$).
    * **What it does:** Creates new columns called "Principal Components."
    * **Best for:** General dimensionality reduction and training acceleration (HIGH MULTI-COLLINEARITY). | `PCA()` |

    > PCA it's the best option for multicollinearity, a problem that some features have high correlation, so thhey have 'the same information', and the model can have problems with that.
    

2. **LDA (Linear Discriminant Analysis):** A **supervised** method. It explicitly uses the target ($y$) to find the best projection.
    * **What it does:** Projects data to **maximize the distance between classes**. It tries to "push" groups apart (e.g., separating the number 4 from the number 9).
    * **Best for:** Pre-processing specifically for classification tasks. | `LinearDiscriminantAnalysis()` |
    

**SKLEARN**
`sklearn.decomposition` (PCA) | `sklearn.discriminant_analysis` (LDA)

### 1.3 SPLIT METHODS (Validation Strategies)
Instead of a single "final exam" (simple Train/Test), you perform several "simulated tests" by rotating the data. This ensures the model actually learned the patterns rather than just memorizing the answers (overfitting).

* **WHY USE IT?**
1. **Robustness:** Ensures performance wasn't just "luck" from a single favorable data split.
2. **Stability Measurement:** Allows you to calculate the Standard Deviation; if accuracy varies wildly between splits, the model is unstable.

**TYPES**
1. **K-Fold:** Divides the dataset into $K$ fixed blocks (folds). Each block serves as the test set once, while the others are used for training.
    * **Rule:** Every single data point is tested exactly once.
    * **Best for:** Small to medium-sized datasets. | `KFold()` |
    

2. **ShuffleSplit:** Performs random and independent shuffles/draws for each round, without being tied to fixed blocks.
    * **Rule:** There may be overlap (a data point might be tested multiple times or not at all).
    * **Best for:** Very large datasets (Big Data). | `ShuffleSplit()` |
    

3. **Stratified (Classification Version):** A "safety lock" applied to K-Fold or Shuffle.
    * **What it does:** Ensures each split maintains the same class proportions (e.g., 10% of each digit in MNIST).
    * **Best for:** **Mandatory for Classification tasks.** | `StratifiedKFold()` | `StratifiedShuffleSplit()` |
    

4. **Time Series Split:** A chronological split where the past trains the future.
    * **What it does:** The training window grows with each round, and the test set is always the subsequent time block. Prevents **Data Leakage**.
    * **Best for:** Stock prices, weather, and sales forecasting. | `TimeSeriesSplit()` |
    

**SKLEARN**
`sklearn.model_selection`
