# Evaluation Metrics in Machine Learning

Evaluation metrics are used to measure the performance of a model. Unlike Loss Functions, metrics are designed to be interpretable by humans to decide if a model is "good enough" for production.

---

## 1. Classification Metrics

Classification metrics are based on the **Confusion Matrix**, which tracks:
* **TP (True Positive):** Predicted 1, Actual 1.
* **TN (True Negative):** Predicted 0, Actual 0.
* **FP (False Positive):** Predicted 1, Actual 0 (Type I Error).
* **FN (False Negative):** Predicted 0, Actual 1 (Type II Error).



### A. Accuracy
The percentage of total correct predictions. Using when classes it's 50/50
$$\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}$$
> **Caution:** Accuracy is misleading for imbalanced datasets (e.g., if 99% of samples are Class 0).

### B. Precision (Exactness)
Of all instances predicted as Positive, how many were actually. Positive? Focuses on **avoiding False Positives**.
Using when false positives are costly (e.g., a fire alarm that sounds without a fire).
$$\text{Precision} = \frac{TP}{TP + FP}$$

### C. Recall (Completeness / Sensitivity)
Of all actual Positive instances, how many did the model find? Focuses on **avoiding False Negatives**.
Using when a false negative is dangerous (e.g., letting a broken glass slip through the production line).
$$\text{Recall} = \frac{TP}{TP + FN}$$

### D. F1-Score (The Balance)
The harmonic mean of Precision and Recall. It is the best metric when you need a balance between the two, especially with imbalanced classes.
Using whenever there is an imbalance (90/10)
$$F1 = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}$$

### E. Confusion Matrix (The Diagnosis Map)
The Confusion Matrix is a tabular layout that allows visualization of the performance of an algorithm. It shows exactly where the model is "confused" by mapping **Actual** classes against **Predicted** classes.

It is the foundation for all classification metrics (Accuracy, Precision, Recall, and F1).

| | Predicted: **Negative** | Predicted: **Positive** |
| :--- | :--- | :--- |
| **Actual: Negative** | **TN** (True Negative) | **FP** (False Positive) |
| **Actual: Positive** | **FN** (False Negative) | **TP** (True Positive) |

> In sklearn some metrics are for binarys output, so we need to define for multiclass `metrics(x, y, average = 'macro)`

## 2. Regression Metrics

In regression, we measure the distance between the predicted continuous value ($\hat{y}$) and the actual value ($y$).

### A. MAE (Mean Absolute Error)
The average of the absolute differences. It is robust to outliers.
$$\text{MAE} = \frac{1}{n} \sum_{i=1}^{n} |y_i - \hat{y}_i|$$

### B. MSE (Mean Squared Error)
The average of squared differences. It heavily penalizes large errors (outliers).
$$\text{MSE} = \frac{1}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)^2$$

### C. RMSE (Root Mean Squared Error)
The square root of MSE. It brings the error unit back to the same scale as the target variable.
$$\text{RMSE} = \sqrt{\text{MSE}}$$

### D. R-Squared ($R^2$)
Represents the proportion of variance for the target variable that's explained by the features. It acts as a benchmark comparing your model to a "naive" model.

#### **Mathematical Formula**
$$R^2 = 1 - \frac{\sum (y_i - \hat{y}_i)^2}{\sum (y_i - \bar{y}_i)^2}$$

Where:
* **$\sum (y_i - \hat{y}_i)^2$ (RSS):** Sum of squared errors from **your model**.
* **$\sum (y_i - \bar{y}_i)^2$ (TSS):** Total sum of squares (errors if you simply predicted the **mean** of $y$).
> Don't rely solely on $R^2$ when the target variable has very low variance. In these cases, even a highly accurate model (low MAE) will show a poor $R^2$ because it can't significantly outperform the simple mean baseline.

## 3. Advanced Visualization Metrics

### ROC Curve & AUC
* **ROC Curve:** A plot of the True Positive Rate vs. False Positive Rate at various thresholds.
* **AUC (Area Under the Curve):** A single value representing the probability that the model ranks a random positive example higher than a random negative one.
    * **AUC = 1.0:** Perfect Classifier.
    * **AUC = 0.5:** Random Guessing.


    This table serves as a general benchmark for model performance across Classification and Regression tasks.

| Category | Metric | What it evaluates | Bad | Mediocre | Good |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Classification** | **Accuracy** | Overall correctness | < 0.60 | 0.70 - 0.80 | > 0.85 |
| **Classification** | **Precision** | Quality (Avoids False Positives) | < 0.50 | 0.65 - 0.75 | > 0.80 |
| **Classification** | **Recall** | Quantity (Avoids False Negatives) | < 0.50 | 0.65 - 0.75 | > 0.80 |
| **Classification** | **F1-Score** | Balance between Prec. & Recall | < 0.50 | 0.60 - 0.75 | > 0.80 |
| **Classification** | **AUC-ROC** | Class separation capability | 0.50 | 0.70 - 0.80 | > 0.85 |
| **Regression** | **R-Squared ($R^2$)** | Goodness of fit (Variance explained) | < 0.30 | 0.50 - 0.70 | > 0.80 |
| **Regression** | **MAE** | Average absolute distance | High* | Moderate | Low |
| **Regression** | **MSE** | Squared error (Penalizes outliers) | High* | Moderate | Low |
| **Regression** | **RMSE** | Error in target units | High* | Moderate | Low |
| **Regression** | **MAPE** | Mean Absolute Percentage Error | > 20% | 10% - 20% | < 10% |

> **\*Note on Regression (MAE, MSE, RMSE):** "Good" or "Bad" values depend entirely on the scale of your target variable. For example, an error of $100 is excellent when predicting house prices, but terrible when predicting the price of a chocolate bar.

> **EVERTHING DEPENDS IN METRICS, THE DATASET, THE DISTRIBUTION, THE VARIANCE, SO IT'S NECESSARY TO ANALYZE ALL THE CONTEXT AND SITUATIOMN BEFORE DETERMINE IF THE MODEL IS GOOD, MEDIUM OR BAD!!!!**
