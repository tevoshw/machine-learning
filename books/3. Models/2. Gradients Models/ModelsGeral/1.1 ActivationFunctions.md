# XOR Problem
As we know **in classification problems** we want to **distinguish classes with lines**, but there is a problem that can stop this, if the **class relations** are **nonlinear**, a **simple line cannot distinguish them** and the model makes poor predictions; we can call this **XOR PROBLEM**

The XOR (Exclusive OR) problem is a historical landmark in Artificial Intelligence. It famously exposed the limitations of simple linear models in the 1960s, eventually leading to the development of modern Deep Learning. It serves as the ultimate proof of why non-linear activation functions and hidden layers are essential.

## 1. The Logic of XOR
Unlike AND or OR gates, the XOR gate is not linearly separable. This means if you plot the inputs on a 2D graph, you cannot draw a single straight line to separate the "0" outputs from the "1" outputs.

For a better visualization: https://seantrott.substack.com/p/perceptrons-xor-and-the-first-ai

## 2. The Solution: NonLinear Functions
To solve a non-linear problem, we simply add a non-linear function to the model. We call in the machine learning world activation functions. But we still with some questions...

1. If non-linear functions are the ones that solve the problem, why not use them alone?

or

2. Or even because we don't use 2-degree functions to solve this problem?


### 2.1 Why not just use non-linear functions?

In classical machine learning, nonlinear functions are essential to capture complex patterns in data. However, using them **alone** is not enough for a few important reasons:

#### 1. Composition of functions
Powerful models arise from **combining linear and nonlinear parts**.  
For example:
- The linear part combines features (weights + sum)
- The non-linear part introduces complexity (activation)

Without the linear part, the model loses the ability to **adjust different weights for each input variable**.

#### 2. Lack of isolated flexibility
A single fixed nonlinear function (such as a parabola) is bounded.  
It can't adapt well to different data formats.

ML models need to be:
- **Flexible**
- **Data Adjustable**

--- 

### 2.2 Why not just use 2nd degree functions?

Quadratic functions (of degree 2) seem like a good idea, but they have important limitations:

**1. Unknow RelationShip:**

We don't know the relationships of the data, many times we can initialize a 2 degree function, but what if the relationship is 5? would we test all possibilities? it wouldn't take much time, so it's  waste of time and money on big problems.

This is very restrictive for real data, which can have:
- Multiple patterns
- Highly complex relationships

# Activation Functions (The Forward Pass "Extra")
O cálculo começa com uma operação puramente linear: $z = W \cdot x + b$. Matematicamente, isso é apenas uma equação da reta (ou um hiperplano em dimensões maiores). O problema é que, se a relação for não-linear, a soma de funções lineares sempre resultará em uma função linear. É aqui que entram as funções de ativação para "quebrar" essa rigidez.

## 1. Como a "Curva" é criada?

As funções de ativação (como Sigmoid, ReLU ou Tanh) funcionam como moldes de deformação. Elas pegam a saída da reta ($z$) e aplicam uma transformação que altera sua inclinação de forma não constante.

1. A Reta se Torna Curva: Imagine uma folha de papel esticada (linear). A função de ativação é como se você dobrasse ou enrolasse esse papel.

2. Criação de Fronteiras Flexíveis: Ao aplicar essa dobra, a rede deixa de ser obrigada a separar os dados com uma linha reta. Ela agora pode criar curvas, círculos ou formatos complexos para contornar os dados.

3. Soma de Não-Linearidades: No Forward Pass, quando você soma as saídas de vários neurônios ativados, você está combinando várias "dobras" diferentes. O resultado final é uma função extremamente complexa que pode se moldar a praticamente qualquer padrão.

## 2. E se for uma curva muito complexa?

Se um problema exige uma curva extremamente específica — como contornar o formato de um rosto ou identificar a caligrafia de um número — uma única função de ativação não será suficiente. No entanto, o não está em usar uma função super complexa, mas sim na soma e multiplicação de várias curvas simples.

**A Soma de Ativações:** 

1. A Soma: Quando você soma duas funções não-lineares (como duas Sigmoids), você pode criar um "degrau", um "buraco" ou um "pico". Se você somar 1.000 dessas funções, você consegue desenhar qualquer formato, por mais estranho que seja.

2. A Multiplicação: Quando as curvas interagem entre as camadas, elas criam relações de dependência. É como se a rede dissesse: "Eu só vou criar esta curva complexa aqui se aquelas outras duas curvas ali atrás também existirem".

> Only some models  have ACTIVATIONS FUNCTIONS, so this isn't a law for ever model e.g. (classification problems in classic ml and neural networks)


## 3. How the class is decided? (Decision Making)

A neural network doesn't just "guess" a category; it follows a mathematical pipeline where each step transforms the data until a decision is made:

### Step 1: Linear Output ($\hat{y}$)
The first calculation ($W \cdot x + b$) generates a raw score called **$\hat{y}$ (y-hat)**. This number can be anything—from -500 to 500. At this stage, it doesn't represent a probability yet, just a "strength" of signal.

### Step 2: Non-Linear Transformation ($\hat{y}_2$ = Probability)
When we pass the raw $\hat{y}$ through a non-linear activation function (like Sigmoid), transform the space and it generates a new value: **$\hat{y}_2$**.
* This **$\hat{y}_2$ is a Probability**. 
* It "squashes" the infinite linear range into a controlled space (between **0 and 1**).
* For example: If $\hat{y}_2 = 0.85$, the model is 85% confident that the input belongs to Class 1.



### Step 3: The Threshold (The Decision Rule)
Even with a probability of 0.85, the model hasn't "chosen" the class yet. It needs a **Threshold (Limiar)** to act as a judge.

* **The Rule:** We set a limit (usually **0.5**) to binarize the result.
* **If $\hat{y}_2 \geq 0.5$:** The model officially predicts **Class 1**.
* **If $\hat{y}_2 < 0.5$:** The model officially predicts **Class 0**.

# Types

## 1. Sigmoid (Binary Classification)
Used in the output layer of binary models. It "squashes" any real-valued number into a range between **0 and 1**, representing the probability of the positive class.
$$\sigma(z) = \frac{1}{1 + e^{-z}}$$
* **Output:** $P \in [0, 1]$
* **Use Case:** Logistic Regression, Binary Neural Networks.


## 2. Softmax (Multiclass Classification)
The multiclass generalization of the Sigmoid. it takes a vector of raw scores (logits) and turns them into a probability distribution where the sum of all components is exactly **1.0 (100%)**.
$$\text{Softmax}(z_i) = \frac{e^{z_i}}{\sum_{j=1}^{K} e^{z_j}}$$
* **Output:** A vector of probabilities $[P_1, P_2, ..., P_K]$.
* **Use Case:** Softmax Regression, XGBoost (multiclass), Deep Learning output layers.


## 3. ReLU - Rectified Linear Unit (Hidden Layers)
The most common activation for deep learning. It filters out negative values, which helps the model learn complex patterns without "vanishing" gradients. Unlike Sigmoid/Softmax, it is rarely used in the final classification output because its range is $[0, \infty)$.
$$f(z) = \max(0, z)$$
* **Output:** 0 for negative inputs, $z$ for positive inputs.
* **Use Case:** Hidden layers in Neural Networks (MLP, CNN).


## 4. Tanh - Hyperbolic Tangent
Similar to Sigmoid but ranges from **-1 to 1**. It is zero-centered, which often makes the optimization process (training) faster in certain neural network architectures.
$$\tanh(z) = \frac{e^{z} - e^{-z}}{e^{z} + e^{-z}}$$
* **Output:** $P \in [-1, 1]$
* **Use Case:** Recurrent Neural Networks (RNNs) and specific hidden layers.
