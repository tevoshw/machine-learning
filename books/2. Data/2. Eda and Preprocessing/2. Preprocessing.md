# Preprocessing
The part where we prepare the data for the final dataset to train and test, like EDA, we have 3 parts.
1. Data Cleaning: Remove and fix the 'broken bricks'
2. Data Engineering: Put in a way that computer can read
3. Data Tunning: Improve the data, simplify them.

> All methods used, you can have in `sklearn.preprocessing` or others libs like pandas and more.

# 1. Data Cleaning (Quality Check)
The goal is to remove noise and inconsistencies that could break the code or mislead the model's learning process.

### 1.1 Features Names
1. Lower the features name: `df.columns.str.lower()`
2. Rename: `df.rename(columns={'old': 'new'})`

### 1.2 Constants features
1. Drop: `.drop()`

### 1.3 Null Values:
1. Fill values: `SimpleInputer(strategy = '')` (Only after split)
2. Remove:  `.dropna`

### 1.4 Duplicates: 
1. Remove: `.drop_duplicated()`

### 1.5 Wrong And Impossible Data

**Negative Data**  
1. Validation Rules: remove or flag values that violate domain constraints (e.g., age < 0)  
2. Replace: set as `NaN` and apply imputation  
3. Removal: `.drop()` if few and clearly wrong  

**Data Entry**  
1. Validation Checks: detect via ranges, inconsistencies, duplicates  
2. Correction: fix manually using domain knowledge (if possible)  
3. Replace/Remove: set as `NaN` and impute or `.drop()` 


> Redudant features are too important to verify, but you can do this at analysis part ! :8

## 2.2 Features Types (Encoders)
Transform simples texts into numbers.

### Features Encoders

- **`OneHotEncoder`** → Used for **nominal data (no order)**. Creates binary columns for each category. Best when categories have no hierarchy (e.g., color, city).  
- **`OrdinalEncoder`** → Used for **ordinal data (has order)**. Assigns integers preserving order (e.g., low < medium < high).  
- **`LabelEncoder`** *(not recommended for features)* → Converts labels to numbers but assumes order implicitly. Mostly used for targets, not features.

### Target Encoders

- **`LabelEncoder`** → Used for **target labels** in classification. Converts classes into numeric values (e.g., A → 0, B → 1). Works for both nominal and ordinal targets, but does not preserve order meaningfully. 

> Note: scikit-learn does **not natively include advanced target encoders** (like mean/target encoding). These are usually from external libraries

## 2.3 Sensibility (Scalers)
Adjust the scaler of the features 

- **`StandardScaler`** → Centers data (mean = 0) and scales to unit variance (std = 1). Good for most models (linear, neural networks).  
- **`MinMaxScaler`** → Scales values to a fixed range (usually 0 to 1). Useful when bounds matter or for neural networks.  
- **`MaxAbsScaler`** → Scales by maximum absolute value (range [-1, 1]). Useful for sparse data.  
- **`RobustScaler`** → Uses median and IQR. Less sensitive to outliers.  
- **`Normalizer`** → Scales each sample (row) to unit norm (L1, L2). Used in text/vector similarity.  

> Note: Tree-based models (e.g., Random Forest, XGBoost) typically do not require scaling.

> Only after the split!!!

## 2.4 Vectorization
Are methods that transform text into numbers for the models (more advanced then Encoders)

### Bag Of Words
The most basic form of vectorization. It creates a "vocabulary" of all unique words in your dataset and counts how many times each word appears in a specific document. It gives equal importance to all words, meaning common words like "the" or "is" can drown out meaningful, rare words.

`CountVectorizer()`


### TF-IDF
TF-IDF is a more sophisticated evolution of Bag Of Words. It scales the importance of a word based on how unique it is to a specific document versus the entire corpus.

- **TF (Term Frequency)**: How often a word appears in a specific document.

- **IDF (Inverse Document Frequency)**:: Reduces the weight of words that appear very frequently across all documents (like "and", "the", "project").

It highlights "signature words" that help the model distinguish between different types of text.

`TfidfVectorizer()`


# 3. Data Tunning
This stage focuses on refining both the **Data** and the **Algorithm** to extract maximum predictive power.

## 3.1 Feature Selection (Types & Methods)

### 1. Filter Methods
Independent of any machine learning algorithm. They rely on the statistical characteristics of the data (**Math only**).
* **Correlation (`.corr()`):** Measures the linear relationship between feature and target.
* **Variance Threshold (`VarianceThreshold()`):** Removes columns where the values don't change much (low variance = low information).
* **SelectKBest:** Selects the $K$ best columns based on statistical tests.
    * *Regression:* `f_regression`, `mutual_info_regression`.
    * *Classification:* `chi2`, `f_classif`.
* **Best for:** Quick "brute-force" removal of irrelevant features before training.

### 2. Embedded Methods
The selection happens **during** the model training. The model itself decides what is important through its internal logic.
* **SelectFromModel (`SFM`):** Uses attributes like `.feature_importances_` (Trees) or `.coef_` (Lasso) to drop features below a certain `threshold`.
* **Best for:** Fast, smart selection that understands the specific logic of the algorithm (Linear vs. Non-linear).

### 3. Wrapper Methods
Use a specific model as a "black box" to evaluate subsets of features iteratively by training and testing multiple times.
* **RFE (Recursive Feature Elimination):** Starts with all features and removes the weakest one by one.
* **SFS (Sequential Feature Selection):**
    * *Forward:* Starts with 0 and adds the best one.
    * *Backward:* Starts with all and removes the worst.
* **Best for:** Maximum precision when you have high processing power and a smaller number of features.
### 4. Feature Importance
This method split the features and test in the model, measures how much each feature influences the model's predictions. It helps us understand which variables the model actually uses to make decisions.

* **`.feature_importances_`** | Measures how much each feature reduces impurity (Gini / Entropy) in tree-based models |
* **`.coef_`** | Represents the weight of each feature in linear models |
* **`permutation_importance`** | Measures how much model performance drops when a feature is randomly shuffled |

These methods are available in **scikit-learn** and work depending on the model type.

| | Importance Method | What It Means |
| :--- | :--- | :--- |
| **Tree Models** | **`.feature_importances_`** | Feature importance based on impurity reduction in decision trees |
| **Linear Models** | **`.coef_`** | Feature influence based on the model's mathematical coefficients |
| **Any Model** | **`permutation_importance`** | Feature importance based on performance drop after shuffling the feature |


> Note: Feature Importance methods do not automatically remove features.
They only measure how much each feature contributes to the model's predictions.
However, by analyzing these importance scores, we can manually select the most relevant features, effectively turning this evaluation into a feature selection strategy.

### **SKLEARN TOOLKIT**
`sklearn.feature_selection` / `sklearn.inspection`

> **The `.fit()` vs `.fit_transform()` Logic:**
> * **Filter Methods:** Since they don't involve training a complex model, we often use `.fit_transform()` to get the data ready in one go.
> * **Wrapper/Embedded:** We use `.fit()` to let the model "learn" the importance, and then we use `.get_support()` to see the winners.

#### **The `get_support()` Bridge:**
Sklearn transforms data into **Numpy Arrays**, which means column names are lost. To recover them, use:

```python
# Returns a boolean mask of the selected columns
mask = selector.get_support()

# Map the mask back to the original DataFrame header
selected_columns = X.columns[mask]

# Rebuild your DataFrame with names
X_new = pd.DataFrame(selector.transform(X), columns=selected_columns)
```

## 3.2 Dimensionality Reduction
**METHODS**
1. **PCA (Principal Component Analysis):** An **unsupervised** method. It ignores the target ($y$) and focuses solely on finding the axes of maximum variance in the data ($X$).
    * **What it does:** Creates new columns called "Principal Components."
    * **Best for:** General dimensionality reduction and training acceleration (HIGH MULTI-COLLINEARITY). | `PCA()` |

    > PCA it's the best option for multicollinearity, a problem that some features have high correlation, so thhey have 'the same information', and the model can have problems with that.
    
2. **LDA (Linear Discriminant Analysis):** A **supervised** method. It explicitly uses the target ($y$) to find the best projection.
    * **What it does:** Projects data to **maximize the distance between classes**. It tries to "push" groups apart (e.g., separating the number 4 from the number 9).
    * **Best for:** Pre-processing specifically for classification tasks. | `LinearDiscriminantAnalysis()` |
    

**SKLEARN**
`sklearn.decomposition` (PCA) | `sklearn.discriminant_analysis` (LDA)
