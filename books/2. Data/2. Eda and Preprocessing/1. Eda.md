## 1. Data Overview
The goal here is to understand the data. In many cases, we receive a dataset without context, only with a problem to solve. Therefore, we must first understand its structure and what it represents.

### Shape
**The shape of a dataset refers to its structural dimensions, representing the number of elements along each axis (rows, columns, and higher dimensions)**

`.shape` returns the shape of dataframe in (rows, columns)

### Data Types
**While Python has standard types like int, float, and str, libraries like NumPy and Pandas use more specific types to optimize memory and processing speed. The data type tells the computer how to interpret the binary stored in memory—whether it should treat a value as a number to be added, a category to be grouped, or a date to be sequenced.**

`.dtypes` for all the dataste and `.dtype` for a single on column (feature)

### Data Samples 
**A sample (also known as an observation, record, or instance) represents a single unit of data in your collection. In a standard 2D dataset, each row is a sample, while each column represents a feature (a characteristic of that sample). For example, in your "Drugs Project," a single sample would represent one specific patient, including their age, sex, and the drug they were prescribed.**

`.head()` View the first N samples

`.tail()` View the last N samples

### Column Names
**Column names provide the essential mapping between raw data and human-readable features. In Machine Learning, these names represent your Independent Variables (features like Age, BMI, or Blood_Pressure) and your Dependent Variable (the Target or Label you want to predict, like Drug_Type). Clear and consistent naming is the first step in successful data cleaning, as it allows you to select, filter, and manipulate specific data points without confusion.**

**A Constant Feature is a column in your dataset where every single row contains the exact same value. In terms of information theory, these features have zero variance. Because they do not change, they provide no predictive power—they cannot help a Machine Learning model distinguish between different classes (like different types of drugs) because the value is the same for every patient**

**Duplicates are identical rows that provide no new information to your Machine Learning model. ## 4. EDA for Data Engineering

This is the stage where we detect and analyze data problems with the specific goal of **fixing them**. Unlike classical EDA (which is exploratory), here we are prescriptive: we understand the problem to know exactly how to preprocess.

### 4.1 Time Series

#### What is it?
Data organized chronologically, where the temporal order of observations is crucial. Examples: stock prices, daily temperature, monthly sales, IoT sensors.

#### Why does it exist?
Many real-world problems involve temporal sequences. Ignoring the time dimension can lead to biased models and poor predictions.

#### What does it serve for in EDA?
- **Detect trends**: consistent growth or decline over time
- **Identify seasonality**: patterns that repeat at regular intervals (weekly, monthly, yearly)
- **Find temporal anomalies**: unexpected spikes or gaps in data
- **Check stationarity**: whether the series has constant mean and variance (important for many models)
- **Analyze autocorrelation**: correlation of the series with itself at previous periods

#### Common problems in Time Series:
```
- Missing data (gaps)
- Duplicate timestamps
- Inverted temporal order
- Abrupt jumps (temporal outliers)
- Distribution shift over time (concept drift)
```

#### Useful tools:
- Temporal line plots
- Stationarity tests (Augmented Dickey-Fuller)
- Time series decomposition (trend + seasonal + residual)
- Autocorrelation plots (ACF/PACF)

---

### 4.2 Features Types (Encoders)

#### What is it?
Classification and treatment of **different data types** in your columns: numerical, categorical, ordinal, text, etc.

#### Why does it exist?
Machine learning algorithms (especially trees and neural networks) cannot directly process categorical data. We need to convert this information into numbers in a way that preserves meaning.

#### What does it serve for in EDA?
- **Identify data types**: distinguish between numerical, categorical, ordinal, text, image columns
- **Detect type inconsistencies**: a column that should be numerical but has text values
- **Understand cardinality**: how many unique values exist in each categorical column
- **Plan the encoding strategy** appropriate for each type

#### Critical decisions:
- Which encoding minimizes information loss?
- How many new columns will be created? (One-Hot can expand data significantly)
- Can the model I'm using handle this encoding?

---

### 4.3 Sensitibility (Scalers)

#### What is it?
The process of **normalizing or standardizing** the scale of numerical features so they're in comparable ranges.

#### Why does it exist?
Many algorithms (KNN, SVM, neural networks, gradient boosting) work better when features have similar scales. A feature ranging 1-1000 can dominate a feature ranging 0-1, creating bias.

#### What does it serve for in EDA?
- **Detect scale disparities**: one column has values 0-1 and another has 0-1,000,000
- **Choose the appropriate scaler** based on data distribution
- **Identify extreme outliers** that can affect scaling
- **Understand the impact** of different scaling strategies


#### Critical decision in EDA:
- Do my data have outliers? → RobustScaler
- Is my data approximately normal? → StandardScaler
- Do I need to be between 0 and 1 explicitly? → MinMaxScaler
- Is my data very skewed? → LogScaler or PowerTransformer

---

### 4.4 OverSampling

#### What is it?
The technique of **duplicating or synthesizing examples** of the minority class in imbalanced classification problems.

#### Why does it exist?
Many datasets have imbalanced classes (e.g., fraud: 99% no, 1% yes). Models trained under these conditions tend to ignore the minority class and always predict the majority class.

#### What does it serve for in EDA?
- **Quantify the imbalance**: ratio between classes
- **Understand the consequences**: which is the minority class? What is its impact?
- **Decide if OverSampling is necessary**: it's not always needed
- **Analyze the impact** of different strategies



#### Alternatives to OverSampling:
- **UnderSampling**: reduce majority class (loses data)
- **Class Weights**: give higher weight to minority class
- **Threshold Tuning**: change model decision threshold
- **Appropriate metrics**: use Precision-Recall, F1, ROC-AUC instead of Accuracy

## 5. EDA for Data Tuning

This stage refines both the **data** and the **algorithm** to extract maximum predictive power. Here you are beyond basic preparation: optimizing features and dimensionality.

### 5.1 Feature Selection

#### What is it?
The process of choosing a **subset of original features** that contribute most to prediction, removing those that don't add value or harm performance.

#### Why does it exist?
- **Curse of Dimensionality**: many features with little data = overfitting
- **Noise**: irrelevant features introduce noise into the model
- **Computational cost**: fewer features = faster model
- **Interpretability**: model with few features is easier to explain
- **Generalization**: model with good features generalizes better

#### What does it serve for in EDA?
- **Quantify importance of each feature**: which contributes most?
- **Identify correlated features**: if two say the same thing, remove one
- **Detect redundant features**: that are linear combinations of others
- **Understand trade-off**: performance vs simplicity


#### Critical decisions:
- How many features do I need? Trade-off problem
- Correlated features: keep one or combine?
- Is the selected feature interpretable?

---

### 5.2 Reduce Dimensionality

#### What is it?
Techniques that **transform original features** into a smaller-dimensional space, maintaining as much information as possible.

#### Why does it exist (different from Feature Selection)?
- **Feature Selection**: chooses a subset of original features
- **Dimensionality Reduction**: TRANSFORMS features into new features of lower dimension

Example:
```
Feature Selection: from [age, weight, height, income] → [age, weight]
Dimensionality Reduction: from [age, weight, height, income] → [PC1, PC2]
(where PC1 and PC2 are combinations of the originals)
```

#### What does it serve for in EDA?
- **Visualize high-dimensional data**: reduce to 2D/3D for plotting
- **Detect hidden patterns**: structure that's not obvious in original features
- **Discard noise**: keep only dimensions with high variance
- **Prepare for clustering/visualization**: understand natural groupings

## Complete EDA Flow for Data Engineering and Tuning

```
1. Initial EDA (Exploration)
   └─ Understand data, distributions, missing values
   
2. Data Engineering (Fixing)
   ├─ Time Series: detect trends, seasonality, gaps
   ├─ Features Types: identify and encode different types
   ├─ Sensitibility: choose and apply appropriate scaler
   └─ OverSampling: balance classes (only on train!)
   
3. Data Tuning (Optimization)
   ├─ Feature Selection: remove non-relevant features
   └─ Reduce Dimensionality: transform to smaller space
   

## EDA Checklist

- [ ] Identified all feature types (numerical, categorical, text, temporal)
- [ ] Detected and treated missing values
- [ ] Analyzed distributions and outliers
- [ ] For time series: detected trends, seasonality, stationarity
- [ ] Chose appropriate encoders for categorical features
- [ ] Chose appropriate scalers for numerical features
- [ ] Balanced classes (if imbalanced classification problem)
- [ ] Selected most relevant features
- [ ] Tested dimensionality reduction if needed
- [ ] Validated that transformations are applied only to train set
- [ ] Documented all transformations performed
